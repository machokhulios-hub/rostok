## Как устроен код
- `index.html` подключает `plan.js`, `courses.js`, `app.js` с `?v=N`; цвета разделов заданы в `:root` как `--c-<cat>`.
- `courses.js` — все курсы. Курс типа `path` = список шагов (урок или экзамен). Урок: `id, t, plan, theory{rule, ex[[a,b]], tip}, ex[вопросы choice/input/order]` (обычно 5). Экзамен: `id, t, exam:true, covers[], pass:0.8, q[]`. В вопросе `choice` ПЕРВЫЙ вариант всегда правильный, приложение перемешивает. Типы `input` и `order` с v4.13 поддержаны и в обычном уроке, и в экзамене. Подробный контракт и пример — ниже. **id уроков и экзаменов менять нельзя**, иначе пропадёт прогресс.
- `app.js`: версия в `APP_VERSION`, список разделов в `CATS`, подсчёт серии в `streak()`.
- `sw.js` — офлайн-кеш, сначала сеть. Имя кеша `rostok-vX-Y`.

## Формат урока и учебного теста для дерева

Актуально для кода v4.13. Источник данных — **`courses.js` в UTF-8**, обычный JavaScript-файл с присваиванием `window.COURSES = [...]`. `index.html` подключает его после `plan.js`, но **до `app.js`**; `app.js` берёт готовый массив из `window.COURSES`. Уроки и учебные тесты — объекты внутри этого массива. Отдельного загрузчика `lesson.html`, `lesson.json`, `test.json` и автоматического поиска файлов по папкам сейчас нет.

### Как материал попадает на дерево

`treeHome()` в `app.js` создаёт пять кнопок с заранее заданными переходами:

| Ветвь | Что открывает | Как включить материал |
| --- | --- | --- |
| Языки | Каталог с `cat: 'eng'` или `cat: 'rus'` | Добавить шаг в существующий курс либо новый курс с подходящим `cat`. |
| Программирование | Каталог с `cat: 'code'` | Например, здесь видны курсы `code` и `vitrina`. |
| ИИ | Конкретный курс `id: 'ai'` | Новые уроки добавлять в `ai.steps`. Другой курс с `cat: 'ai'` сам к этой кнопке не подключится. |
| Музыка | Конкретный курс `id: 'music'`, сейчас `type: 'stages'` | Это этапы треков, не учебный путь. Для отдельного курса музыки потребуется изменить переход ветви. |
| Творчество | Каталог с `cat: 'poem'`, `'read'`, `'music'`, `'book'` | Включает классику `poemlib`, у которой `cat: 'poem'`. |

Дерево не строит новые ветви автоматически из названий файлов или курсов. Фильтры задаёт `FILTER_CATS`. `cat` — категория для фильтра, цвета и иконки; `id` — постоянный идентификатор конкретного курса. Новый курс добавляй **в существующий** `window.COURSES`, не заменяй весь массив примером ниже. Описание карточки хранится отдельно в `DESC[course.id]`, обложка — в `PHOTO[course.id]`; без них курс работает с пустым описанием и стандартной иконкой.

Подпись процента на ветви программирования относится к курсу `id: 'code'`, а не ко всем курсам категории. С v4.15 на главной только дерево с пятью ветвями на телефоне и компьютере. Звания, XP, предпросмотр роста и кнопка продолжения находятся в «Профиле»; там же доступны план, избранное и достижения. Кнопка продолжения ищет следующий доступный шаг через `resumeTarget()` с учётом `lastStudy`; имя файла на её выбор не влияет.

### Объект курса

Для курса с уроками используй `type: 'path'` и непустой `steps` в порядке прохождения.

| Поле | Формат и назначение |
| --- | --- |
| `id` | Уникальная строка курса, например `web-basics`. Сохранять после публикации. |
| `cat` | Существующая категория, например `code`; она определяет попадание в фильтруемые ветви. |
| `name`, `goal` | Строки с названием курса и целью. |
| `type` | Строка `'path'` для уроков и экзаменов. Другие типы (`books`, `counter`, `stages`) имеют другой формат. |
| `unit` | Обычно `'урок'`; `'правило'` меняет подписи в интерфейсе. |
| `prompt` | Обязательная строка: `stepHero()` вызывает у неё `.replace()`, даже если урок встроенный. Подстановки: `{n}`, `{t}`, `{plan}`, `{words}`. Каждое вхождение заменяется только один раз, поэтому не дублируй один маркер в шаблоне. |
| `steps` | Массив объектов уроков и экзаменов; см. ниже. |
| `level`, `target` | Необязательные строки для плашки уровня и цели, например `A0`, `A1`. |
| `resources` | Необязательный массив `{ href: 'vitrina/index.html', label: 'Редактор кода' }`. Показывает ссылки на странице курса; содержимое HTML по ссылке не превращается в урок и не передаёт результаты в дерево автоматически. Пути считаются от страницы приложения. |

### Объект урока и его проверочные вопросы

- `id`, `t`, `plan` — постоянный идентификатор, заголовок и план/ожидаемый результат урока. Номер отдельно не задаётся: его вычисляет положение среди уроков в `steps`, пропуская экзамены.
- `theory.rule` — строка объяснения; `theory.ex` — обязательный массив пар `[пример, пояснение]`, допустим пустой `[]`; `theory.tip` — необязательная строка подсказки.
- **Не путать два `ex`:** `theory.ex` содержит примеры, а `lesson.ex` — массив проверочных вопросов.
- Для `choice` в `lesson.ex` вопрос содержит `k: 'choice'`, `q: 'Текст вопроса'`, `options: ['правильный', 'неправильный', ...]`. Только один ответ правильный, **всегда `options[0]`**. При показе варианты перемешиваются. Нужны различимые варианты, минимум два; обычно готовим 3–4 варианта и 5 вопросов на урок. Число 5 — соглашение автора, код не требует ровно пяти; для полноценного урока массив должен быть непустым.
- Необязательное `explanation` (либо `why`) в вопросе задаёт пояснение к ответу. При отсутствии приложение повторяет правило и первый пример из `theory`.
- **С v4.13 обычный урок поддерживает `choice`, `input` и `order`.** У старых `choice`-вопросов и сохранённых сессий отсутствие `k` трактуется как `choice`. У `input`/`order` явно указывай `k` и поля по примерам ниже; `options` им не нужны.

```js
// Ввести ответ самостоятельно; a — массив допустимых ответов.
{ k: 'input', q: 'Какой атрибут задаёт адрес ссылки?',
  a: ['href'], explanation: 'href хранит адрес перехода ссылки.' }

// Собрать фразу из отдельных слов/фрагментов; a — строка.
{ k: 'order', q: 'Собери заголовок товара',
  words: ['<h1>', 'Товар', '</h1>'], a: '<h1> Товар </h1>',
  why: 'Открывающий тег, текст, закрывающий тег.' }
```

`input` проверяется кнопкой «Проверить ответ» или Enter; `order` — после выбора слов той же кнопкой. Пустой ввод и пустая сборка не считаются ответом. Слова можно убирать из собранной фразы; повторяющиеся слова учитываются по отдельным индексам. Проверка обоих типов использует тот же `norm()`, что и экзамен (регистр, `ё/е`, пробелы и перечисленные ниже знаки пунктуации). Пояснение для каждого типа: `explanation`, затем `why`, иначе правило и первый пример из `theory`.

Черновики текста и сборки сохраняются в `st.session` и восстанавливаются после перезагрузки вместе с проверенными ответами. Проверенный ответ блокируется до повтора ошибок. При повторе неверные ввод/сборка очищаются, первая оценка сохраняется. Старая сессия с другими типами, допустимыми ответами или набором слов отбрасывается, чтобы не оценивать урок по устаревшему ключу. Формат `st.practice` остаётся прежним.
- `words` — необязательный массив троек `[слово, русская транскрипция, перевод]`. Используется в запросе к Claude; словарь приложения собирается из пройденных уроков курса `eng`.

Текст `rule`, `tip` и пояснения к вопросам поддерживает только простое `**жирное выделение**`. Произвольный HTML экранируется; полноценный Markdown (ссылки, списки, таблицы) не разбирается. Примеры `theory.ex` показываются обычным текстом, а при `cat: 'code'` — блоками кода с копированием, **без выполнения кода**. В строках JavaScript экранируй кавычки; для переноса строки используй `\n` или шаблонную строку.

### Отдельный тест по блоку — экзамен

Экзамен — ещё один объект в `course.steps`, обычно после уроков блока:

| Поле | Формат и назначение |
| --- | --- |
| `id`, `t` | Постоянный уникальный идентификатор экзамена и его заголовок. |
| `exam` | Именно `true`, чтобы шаг обрабатывался как экзамен. |
| `covers` | Массив **id уроков этого курса**, например `['web-basics-01']`. Пока они не отмечены пройденными, экзамен ждёт. Несданный предыдущий экзамен закрывает последующие шаги. |
| `pass` | Доля правильных ответов от 0 до 1, обычно `0.8`, то есть 80%. Требуется `ceil(pass * q.length)` правильных ответов; для трёх вопросов при `0.8` нужны все три. |
| `q` | Непустой массив вопросов. Пустой `[]` показывает «скоро», начать такой экзамен нельзя. |

У каждого вопроса экзамена есть `k`, `q` и **`s` — id проверяемого урока**, а не номер или id экзамена. По `s` выбирается теория для пояснения, считаются слабые темы и назначается повторение.

Поддержаны три типа:

```js
// Выбор одного ответа. Правильный всегда первый; приложение перемешает.
{ k: 'choice', s: 'web-basics-01', q: 'Что задаёт структуру страницы?',
  options: ['HTML', 'CSS', 'JavaScript'] }

// Ввод текста. a — массив допустимых ответов, а не одна строка.
{ k: 'input', s: 'web-basics-01', q: 'Напиши название языка разметки',
  a: ['HTML'] }

// Сборка фразы. words перемешивается, a — строка правильной фразы.
{ k: 'order', s: 'web-basics-01', q: 'Собери утверждение о HTML',
  words: ['HTML', 'задаёт', 'структуру'], a: 'HTML задаёт структуру' }
```

Для `input` и `order` сравнение не учитывает регистр, `ё/е`, лишние пробелы и знаки `.,!?;:«»"'`. Синонимы и произвольный код автоматически не оцениваются: в `input.a` перечисляй допустимые формулировки. Для `order` фраза должна собираться из `words` с учётом количества повторяющихся слов. Пояснение в экзамене берётся из теории урока по `s`; поля `explanation`/`why` исходного вопроса экзамена сейчас не переносятся в сессию.

### Полный пример курса с уроком и экзаменом

Это самостоятельный пример синтаксиса файла. В рабочем `courses.js` добавляется только объект курса внутри существующего массива, чтобы остальные направления сохранились.

```js
window.COURSES = [
  {
    id: 'web-basics', cat: 'code', name: 'Основы страницы', type: 'path',
    unit: 'урок', goal: 'Отличать структуру, оформление и поведение страницы',
    prompt: 'Разбери урок {n}: {t}. План: {plan}. Не переписывай код за меня.',
    steps: [
      {
        id: 'web-basics-01', t: 'HTML и первая страница',
        plan: 'Создать заголовок магазина и объяснить назначение трёх языков',
        theory: {
          rule: '**HTML** задаёт структуру, CSS — оформление, JavaScript — поведение.',
          ex: [['<h1>Магазин</h1>', 'h1 — главный заголовок страницы']],
          tip: 'Добавь свой заголовок и открой файл в браузере.'
        },
        ex: [
          { k: 'choice', q: 'Что задаёт структуру?', options: ['HTML', 'CSS', 'JavaScript'],
            explanation: 'HTML описывает содержимое и структуру страницы.' },
          { k: 'choice', q: 'Что задаёт цвета?', options: ['CSS', 'HTML', 'JavaScript'] },
          { k: 'choice', q: 'Что добавляет обработку клика?', options: ['JavaScript', 'CSS', 'HTML'] },
          { k: 'choice', q: 'Какой тег — главный заголовок?', options: ['<h1>', '<p>', '<a>'] },
          { k: 'choice', q: 'Как посмотреть локальный HTML?', options: ['Открыть в браузере', 'Открыть в аудиоредакторе', 'Сменить расширение на .jpg'] }
        ]
      },
      {
        id: 'web-basics-x1', exam: true, t: 'Проверка основ',
        covers: ['web-basics-01'], pass: 0.8,
        q: [
          { k: 'choice', s: 'web-basics-01', q: 'Что задаёт структуру страницы?',
            options: ['HTML', 'CSS', 'JavaScript'] },
          { k: 'input', s: 'web-basics-01', q: 'Напиши название языка разметки', a: ['HTML'] },
          { k: 'order', s: 'web-basics-01', q: 'Собери утверждение о HTML',
            words: ['HTML', 'задаёт', 'структуру'], a: 'HTML задаёт структуру' }
        ]
      }
    ]
  }
];
```

### Результаты, совместимость и проверка подключения

- `id` уроков и экзаменов уникальны **во всём приложении**, а не только в курсе: результаты лежат в общих словарях. Для новых id используй простой вид `web-basics-01`/`web-basics-x1`, без `:` (двоеточие разделяет части адресов действий). Не переименовывай опубликованные id ради новых заголовков.
- Для урока завершение доступно после ответа на все вопросы, **без обязательного процента правильных**. При первом завершении сохраняется дата в `st.lessons[lesson.id]` и начисляется 20 XP. Оценка, индексы ошибок и до 30 попыток лежат в `st.practice[lesson.id]`. Повтор только ошибок не повышает первую оценку текущего прохождения; новое полное прохождение записывает новую попытку.
- Экзамен сохраняет лучший и последний результаты, признак сдачи и до 20 попыток в `st.exams[exam.id]`. Повтор только ошибок не меняет оценку или число попыток. Однажды сданный экзамен остаётся сданным даже после неудачной полной пересдачи. Успешный экзамен даёт вклад в XP по лучшему результату: 10 за правильный ответ; это не накопительная награда за каждую пересдачу.
- Всё это хранится в `localStorage['dnevnik-state']`. Незавершённый обычный урок — `st.session`; последнее открытое занятие — `st.lastStudy`. Это данные пользователя, **не часть файла содержания**. Черновик экзамена не сохраняется для продолжения после перезагрузки. Изменение текста/порядка вопросов может сбросить несовместимую незавершённую сессию; существенные изменения уже пройденного экзамена требуют отдельного решения о миграции результатов.
- Если у урока нет `theory` или `ex`, включается прежний сценарий занятия через Claude и ручной отметки. Это не готовый встроенный урок. Не добавляй заглушки в `steps` как завершённые материалы: они попадут в знаменатель прогресса курса.
- Чтобы выпустить **изменённое содержание**, выполни шаги версии и кеша ниже. Для новой ссылки `resources` файл должен реально существовать в репозитории; включи нужные файлы в `sw.js`, если они должны открываться без сети.
- Проверка: `node --check courses.js`, `node --check app.js`, `npm test`; затем открыть ветвь → курс → урок → ответы → завершение → экзамен и проверить восстановление прогресса. Автотесты разработки находятся в `app.test.cjs` и `sw.test.cjs`; они **не являются учебными тестами** и дерево их не загружает.

## Как выпускать версию (всегда все четыре шага)
1. `APP_VERSION` в `app.js`.
2. `?v=N` в трёх тегах script в `index.html`.
3. `?v=N` в списке файлов и имя кеша `rostok-vX-Y` в `sw.js`.
4. Проверка: `node --check courses.js app.js`, открыть в браузере на ширине 390 и 1280, потом commit и push в main.
